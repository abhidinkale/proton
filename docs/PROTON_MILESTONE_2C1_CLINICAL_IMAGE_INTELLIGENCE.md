# Proton V2 Milestone 2C-1: Clinical Image Intelligence

## 1. Executive Summary

Milestone 2C-1 builds the first clinical image-intelligence layer for Proton V2 on top of the Milestone 2B-2 secure multimodal capture foundation.

Prior pipeline state (M2B-2):
$$\text{Phone Camera} \longrightarrow \text{Secure Upload} \longrightarrow \text{Image QC} \longrightarrow \text{FHIR Media} \longrightarrow \text{FHIR Provenance}$$

M2C-1 clinical intelligence pipeline:
$$\text{FHIR Media} \longrightarrow \text{Authoritative Context} \longrightarrow \text{Pre-AI 9-Step Gate} \longrightarrow \text{Vision AI} \longrightarrow \text{Schema Validation} \longrightarrow \text{Clinical Safety Gate} \longrightarrow \text{Preliminary FHIR Observation} + \text{Provenance} \longrightarrow \text{Cryptographic Audit}$$

---

## 2. Fundamental Clinical Authority Rules

1. **Strict Decision Support Only**:
   AI image analysis outputs are diagnostic recommendations intended strictly for physician review.
2. **Prohibited Autonomous Actions**:
   The AI vision layer is programmatically blocked from:
   - Creating active FHIR `Condition` resources.
   - Creating FHIR `MedicationRequest` resources.
   - Prescribing medications or generating dosage orders.
   - Declaring confirmed, final, or active diagnoses.
3. **Unconfirmed Differentials**:
   All differentials generated by the vision provider are stamped with `status: "unconfirmed"` and require attending physician sign-off.
4. **Authoritative Context Binding**:
   Patient ID, encounter ID, and organization tenant ID are derived strictly from server-authenticated actor context and authoritative storage records. Client-injected identifiers are discarded.

## 3. Architecture & Service Boundaries

Located under `apps/api/services/vision/`:

```
apps/api/services/vision/
├── visionService.js     # Pipeline orchestrator & pre-AI 9-step validator
├── visionProvider.js    # Pluggable provider abstraction (Demo & Gemini)
├── visionSchema.js      # Strict schema & confidence validator
├── visionSafety.js      # Deterministic post-AI clinical safety gate
├── visionAudit.js       # Tamper-evident audit logging (zero leakage)
└── index.js             # Unified module exports
```

### 3.1 Pre-Provider 9-Step Validation
Before any media buffer is dispatched to a vision provider, `VisionService` enforces:
1. **Media Existence**: Media record must exist in durable storage registry (`MEDIA_NOT_FOUND`, 404).
2. **Tenant Quarantine**: Media tenant must match authenticated actor tenant (`CROSS_TENANT_ACCESS_DENIED`, 403).
3. **Patient Ownership**: Media patient binding must match requested patient, and patient must exist in FHIR clinical context (`CROSS_PATIENT_ACCESS_DENIED`, 403; `PATIENT_NOT_FOUND`, 404).
4. **Encounter Consistency**: If encounter ID is provided, it must match media encounter binding (`ENCOUNTER_MISMATCH`, 400).
5. **MIME Type Whitelist**: Permitted MIME types are strictly restricted to `image/jpeg`, `image/png`, and `image/webp` (`INVALID_MIME_TYPE`, 400).
6. **Size & Dimensions Gate**: Size must satisfy $1\text{ KB} \le \text{size} \le 15\text{ MB}$, and dimensions must satisfy $200\times 200 \le \text{dim} \le 8192\times 8192$ (`IMAGE_SIZE_INVALID` / `IMAGE_DIMENSIONS_INVALID`, 400).
7. **Storage File Existence**: Physical asset file must exist on storage disk (`MEDIA_FILE_MISSING`, 404).
8. **Buffer & Checksum Integrity**: File buffer is retrieved and verified for non-empty content and length consistency (`MEDIA_CORRUPT`, 400).
9. **Zero Invalid Image Dispatch**: Malformed, corrupt, or unauthorized images are never forwarded to upstream vision models.

### 3.2 Structured Output Schema
Outputs must conform to the canonical clinical vision schema:
- `observations`: Array of descriptive findings with severity annotations.
- `anatomicalLocation`: Identified anatomical region and laterality.
- `confidence`: Mandatory float $0.0 \le c \le 1.0$. Missing or out-of-range confidence triggers `MISSING_CONFIDENCE` / `INVALID_CONFIDENCE` (422).
- `uncertaintyDescription`: Explicit narrative of visual diagnostic limitations.
- `differentialSuggestions`: Array of conditions with likelihood and mandatory unconfirmed status.
- `limitations`: Explicit disclosures regarding photographic 2D limitations and lack of dermoscopy/histopathology.
- `imageQualityObservations`: Lighting, focus, and clarity assessment.
- `modelMetadata`: Provider, model identifier, and execution latency.
- `timestamp`: ISO-8601 evaluation timestamp.

### 3.3 Post-AI Deterministic Safety Gate
1. **Fabricated Patient Identifier Detection**: Output strings and objects are scanned for unauthorized patient ID references (`FABRICATED_PATIENT_IDENTIFIER`, 400).
2. **Autonomous Diagnosis Rejection**: Provider attempts to return `confirmed`, `final`, `definitive`, or `active` diagnoses are rejected (`AUTONOMOUS_DIAGNOSIS_REJECTED`, 400).
3. **Autonomous Prescription Rejection**: Provider attempts to prescribe drugs, dosages, or sig instructions are rejected (`AUTONOMOUS_PRESCRIPTION_REJECTED`, 400).

### 3.4 FHIR Representation
- Creates preliminary FHIR `Observation`:
  - `status: "preliminary"`
  - `code: LOINC 72170-4` ("Photographic image findings")
  - `derivedFrom: Media/<mediaId>`
  - `note`: "AI Decision Support: Preliminary photographic visual findings. Requires attending physician clinical correlation. Not a confirmed diagnosis."
- Creates FHIR `Provenance`:
  - `target: Observation/<obsId>`
  - `entity.what: Media/<mediaId>` (role: `source`)
  - `agent: Device/<provider>-<model>` (role: `assembler`)
- **Zero active Condition or MedicationRequest resources are generated.**

### 3.5 Tamper-Evident Audit Logging
Every analysis attempt records an immutable cryptographic event in the SHA-256 audit chain:
- `CLINICAL_PIPELINE_VISION_ANALYSIS_STARTED`
- `CLINICAL_PIPELINE_VISION_ANALYSIS_COMPLETED`
- `CLINICAL_PIPELINE_VISION_ANALYSIS_FAILED_*`
- **Zero-leakage guarantee**: Raw image buffers, binary base64 chunks, API keys, and authorization tokens are strictly omitted from audit payloads.
